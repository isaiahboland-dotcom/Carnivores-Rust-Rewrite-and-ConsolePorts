# v0.5.3

Desktop release bundles, texture import fixes, and broader original-engine
regression coverage.

## Desktop downloads

- A shared packager produces `windows.zip` and `linux.tar`, with the launcher,
  PC engine, experimental VR engine, cooker, console-builder interfaces, recipes
  and base-game hash lists. A manifest records file hashes and the revision.
- The release workflow builds both platforms from the release tag, waits for
  both builds, and attaches both archives to the existing release. It also
  supports manual builds for validation before publication.
- Packages use an explicit file list and tracked recipes. They contain no game
  or mod assets, `source/` content or personal recipe instances.
- The Windows build uses the static MSVC runtime. The local cross-built test
  executables import Windows system DLLs without separate Visual C++ runtime
  DLL imports. The launcher currently opens a console window for diagnostics.
- Console applications and third-party packaging tools are separate downloads
  or builds. Including the builder interfaces does not make console packaging
  self-contained. See [the bundle guide](../BUNDLE.md).

## Texture imports and regression tools

- Imported APK models keep opaque black and near-black texels visible instead
  of turning them into the CAR transparency key. Texture lookup also tries a
  model's internal name when its filename has no matching texture.
- Synthetic tests cover APK-to-CAR serialization and runtime texture preparation.
  The `texture-review` command captures deterministic model poses from both sides,
  with configurable image-difference tolerances and local HTML reports.
- Local texture review tools support original-engine captures, compact summaries,
  and verified lossless archives. Reports, owned model files and captures remain
  private; successful capture alone does not establish human visual approval.
- Behaviour scenarios and comparisons extend walking/running, death and settled
  body checks against original engines, including MEE. Kill checks retain model
  and clip diagnostics. These tools do not establish parity for every pack.
- Engine builds record their source revision and development-tree status.

## Steam Deck

The installation guide documents updating the launcher and recommends setting
instance paths in Desktop Mode. File-picker behaviour in Big Picture and controller
mapping still need work; a custom controller layout is currently recommended.

## Since v0.5.2

- PC maps can use more than 254 object types through `.OBX`/`.RSX` side files.
  `c2-pc area-layers` combines map-editor layers into those files. Existing maps
  keep loading normally; 3DS and Wii U packs retain their existing object limits.
- Skipping base parts also moves the phone-menu sprites with the retained parts.
- Original-engine tour scenarios support Modder's Edition executables, with a
  corrected initial camera position. Spawn diagnostics cover MEE games, and
  synthetic tests cover 200 character entries.
- README platform screenshots were added since the previous release.

## Validation and limits

Local PC workspace formatting, Clippy with warnings denied (default and all
features), 556 locked all-feature tests, cooker tests and all 26 Python utility
tests pass. Portable core/VFS checks, portable Wii U C tests, the original-engine
Windows hook build, and Linux release builds for the engines, launcher and
cooker also pass. No dependency versions changed in the release version bump.

The local Windows x64 release cross-build succeeded. Archive tests verify file
selection, required tools and Linux executable permissions. Hash verification
covered all 32 packaged files, and PE import inspection covered all six Windows
executables. A user VM test confirms the launcher opens. This test build came
from the development working tree before the release version bump; it is not
an exact-tag release artifact.

Entering a hunt through the new Windows bundle, clean-machine setup on both
systems, native Windows CI for this revision, and exact-tag archive validation
remain pending. Physical Windows gameplay and performance testing are planned
separately. VM startup does not establish performance or compatibility with
every graphics driver. Earlier Windows VM logs used software rendering.

The release workflow has been prepared locally and has not run on GitHub yet.
Rebuild and validate the tagged revision before attaching public binaries.
README's GUI installation recommendation remains unchanged until validated
archives are publicly available. See [the release checklist](../RELEASING.md).

Recipe edits and personal recipe copies are excluded from this release commit.
No new console or Android hardware acceptance is claimed by this release.
