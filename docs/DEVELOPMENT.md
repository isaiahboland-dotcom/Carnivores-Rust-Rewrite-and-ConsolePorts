# Development guide

The design spec and conventions for working on this project. For what the
project is and how to install it, see the [README](../README.md); for
mods and recipes, [MODDING.md](MODDING.md); for the reasons behind
choices, [DECISIONS.md](DECISIONS.md). If something here conflicts with
what the original game does, **the original wins**: note the discrepancy
in `DECISIONS.md`.

## 1. What this is

A ground-up Rust reimplementation of **Carnivores 2** (Action Forms, 1999), built around a **first-class mod system** that can combine many community mods automatically. It targets:

1. **PC first** (Linux/Windows) — the reference platform and modding workbench.
2. **Nintendo 3DS second** (homebrew, New 3DS primary, Old 3DS best-effort) — same core, thin platform layer.
3. Later: **Wii U** (homebrew; `wiiu-ver/`, `docs/WIIU.md`), **PC VR** (OpenXR; `pc-ver/crates/c2-vr`) and
   **PS VR2** (`psvr2-ver/gameplan.md`, not started).

The original C++ source (made available on Assembla in 2013) is used **as a reference only** to match behavior and file formats. This is a rewrite, not a line-by-line translation.

### Goals
- Faithful vanilla Carnivores 2 gameplay, loading **original game data supplied by the user**.
- Data-driven engine: no hardcoded dino/weapon/area slot limits.
- Automatic mod merging via a layered virtual filesystem + manifests + conflict resolver.
- Targets **add-on mods**: small, data-only mods that layer on vanilla and merge cleanly.
- Plays game folders made for the community **Modder's Edition Engine** (MEE), whose `_RES.TXT` dialect (spawn / pack / trophy tables, `overwrite` sections, new AI families, extended weapons) many full-game mods use. Reimplemented from its public source and manual, read as reference only (like the original source).
- Whole games made from Carnivores 2 (standalone mods) can be added beside it too (`docs/MODDING.md`); most
  should work as they come.
- **Recipes**: shareable modpack definitions that reference mods by hash, so users fetch the mod files themselves and nothing third-party is redistributed.
- A PC-side **cooker** that converts a merged game into 3DS-ready data.
- Launchers (GUIs) so nobody needs the command line: play on PC, build 3DS and Wii U installs.
- One shared core crate; platform crates stay thin.

### Non-goals (for now)
- Carnivores 1 / Cityscape support (keep formats extensible, but don't build it yet). Ice Age is supported (M14).
- Supporting mods that depend on patched executables (other than the Modder's Edition Engine above). Instead, reimplement the *feature* those patches added when it's worth it, behind a manifest flag.
- Multiplayer, online features, new renderer effects beyond what's needed.

## 2. Legal / distribution rules (hard rules)

- **Never commit game data or mod files.** No `HUNTDAT/`, no `.CAR`, `.3DF`, `.MAP`, `.RSC`, `.TGA`, `.WAV` from the game or any mod. `.gitignore` must block these.
- **Never commit the original C++ source.** It lives locally in `source/c2-source/` (gitignored).
- Users supply their own copy of Carnivores 2 and their own mod downloads.
- Recipes contain only: mod names, author credit, source URLs, file hashes, load order, and merge rules/patches written by us.
- Every recipe must credit mod authors. README of any published recipe links to the original mod pages.
- Test fixtures must be **synthetic** (generated by our own code) — never real game files.

### Setting up `source/` (for anyone cloning this repo)
1. Copy your own Carnivores 2 install to `source/c2-original/` (it must contain `HUNTDAT/`).
2. Optionally clone the original source for reference:
   `git clone https://github.com/videogamepreservation/carnivores2 source/c2-source`
3. Put each mod you own in its own folder under `source/mods/`.
4. Optional: your Carnivores: Ice Age install in `source/ice-age/`, your own mobile game APKs in
   `source/mobile/`.
5. Check everything parses: `cd pc-ver && cargo run --release -p c2-parity -- scan ../source/c2-original ../source/mods`

ReShade or other wrapper DLLs in your install are ignored (see `docs/DECISIONS.md`).

### Viewers and debugging (M2)
```
cd pc-ver
cargo run --release -p c2-pc -- model ../source/c2-original/HUNTDAT            # browse every .CAR/.3DF
cargo run --release -p c2-pc -- area  ../source/c2-original/HUNTDAT/AREAS/AREA1.MAP [--dusk|--night]
```
Model viewer: drag to orbit, wheel to zoom, `[` `]` previous/next file, `N`/`P` animation, `Space` pause.
Area viewer: `WASD` + `Q`/`E` to fly, drag to look, wheel = speed, `Shift` = fast, `+`/`-` view distance.
Playing, the gamepad layout, the launchers and `.cia` builds: see the [README](../README.md).

Hunt mode directly (debugging): `cargo run --release -p c2-pc -- hunt ../source/c2-original/HUNTDAT/AREAS/AREA1.MAP` —
click to capture the mouse, `WASD` move, mouse look, `LMB` fire, `E` show/hide weapon, `1`-`6` choose weapon, `Q` weapon-pick screen (lists every carried weapon),
`B` binoculars (`+`/`-` power), `Tab` map, `Alt` call (`C` switch call), `Shift` toggles run, `X` crouch, `Space` jump/swim, arrows turn/look, `Pause`/`P` pause, `Esc` exit prompt (`Y` leave and save, `R` restart).
Without the menu, pick hunt targets with `--target 18` (AI numbers, comma-separated, or `all`), the hunter with `--player N`;
`hunt .../TROPHY.MAP` opens the trophy room (`R` removes the trophy in front of you, `Esc` leaves).
Saves go to `~/.local/share/c2rs/trophy0N.sav` (first run copies your game's saves; the game folder is never written).
Add `--shot out.png` to render one frame to a file instead of opening a window.

## 4. Crate responsibilities

### `c2-formats`
Parsers (and writers where useful) for Carnivores 2 data. Verify every field against `source/c2-source/` and document in `docs/FORMATS.md`.

Expected formats (confirm exact layout from source):
- `.CAR` — animated character models (dinosaurs, hunter/weapon animations): geometry, texture, animations, sounds.
- `.3DF` — static 3D models.
- `.MAP` / `.RSC` — area heightmap/terrain data and the area's resources (textures, objects, sky, etc.).
- `_RES.TXT` — text config defining dinosaurs, weapons, prices, stats.
- `.TGA`, `.WAV` — standard formats; use existing crates where sensible.

Requirements:
- Zero-copy or near-zero-copy parsing where practical (`bytes`/slices), explicit endianness.
- Fallible everything: `Result<T, FormatError>` with file offset + context. Mods ship malformed files; never panic on input.
- Round-trip tests (parse → write → parse) using synthetic fixtures.
- Keep it platform-agnostic so it compiles for `armv6k-nintendo-3ds`.

### `c2-vfs`
Layered virtual filesystem.
- Layers stack in order: `base game` → `mod 1` → `mod 2` → … → `user overrides`.
- Case-insensitive path lookup (original game assumes Windows paths).
- Tracks provenance: for any resolved file, which layer it came from (for conflict reports and debugging).
- Backends: directory on disk, zip archive (mods often ship zipped), and a cooked-pack backend for 3DS.

### `c2-mods`
- **Manifest** (`mod.toml`) per mod: identity, what it adds/replaces, deps, conflicts, required engine features.
- **Auto-detect**: if a mod has no manifest, infer one by diffing its files against the vanilla set (new vs replaced files, new `_RES.TXT` entries). Write the inferred manifest out so the user can tweak it.
- **Resolver**: dependency ordering, conflict detection.
- **Merger**:
  - File-level: last layer wins, unless a merge rule says otherwise.
  - `_RES.TXT`-level: merge entries by ID, not by file. Two mods adding different dinos → both kept. Two mods changing the same dino → conflict, resolved by recipe rule or user choice.
  - Emits a human-readable **merge report** (what came from where, every conflict + how it was resolved).
- **Recipes** (see §6).

### `c2-core`
Platform-independent game: world/terrain, dinosaur AI, hunter, weapons, ballistics, calls/scents/camouflage, scoring/trophies, menus' state machine, saves.
- **Registries, not arrays**: `DinoRegistry`, `WeaponRegistry`, `AreaRegistry` built from merged data, keyed by string IDs. No fixed counts.
- Fixed-timestep simulation; rendering interpolates. Determinism matters for the parity harness.
- No direct I/O — everything through `c2-platform` traits and `c2-vfs`.

### `c2-platform`
Traits only: `Renderer`, `Audio`, `Input`, `Fs`, `Clock`, `Log`. Keep the renderer API small and close to what the game needs (terrain chunks, skinned/animated models, sprites/UI, fog, sky) so the PICA200 backend stays feasible.

### `c2-pc`
Default stack (Claude Code may swap if justified in `DECISIONS.md`):
- `winit` + `wgpu` for windowing/rendering
- `kira` or `cpal` for audio
- `gilrs` for gamepad
- Debug overlay (FPS, current layer provenance of loaded assets, AI state) behind a flag.
- Mod manager UI can start as CLI flags; GUI later.

### `c2-3ds`
- Toolchain: Rust nightly, target `armv6k-nintendo-3ds`, `cargo-3ds`, crates from the **rust3ds** org (`ctru-rs`, `citro3d-rs`). Requires devkitARM/libctru installed.
- Loads **cooked** data only (from `c2-cook`), from `sdmc:/3ds/c2rs/`.
- Controls: Circle Pad move, C-Stick/ZL/ZR on New 3DS, optional **gyro aim**, touch screen fallback aim.
- Bottom screen: map, binoculars/dino locator, inventory, mod/pack picker at boot.
- Optional stereoscopic 3D for terrain depth (toggle, off by default for perf).
- Must respect memory budget: Old 3DS ~64 MB app RAM, New 3DS ~124 MB extended mode. Document real numbers in `docs/3DS.md`.

### `c2-cook`
CLI run on the user's PC:
```
c2-cook --game source/c2-original --recipe recipes/my-pack.toml --mods source/mods --target n3ds --out out/pack
```
- Applies recipe → merged VFS → converts to 3DS formats.
- Textures → PICA-native formats (ETC1/ETC1A4/RGB565, swizzled), downscaled per target profile.
- Model/terrain → pre-baked vertex buffers in a 3DS-friendly layout.
- Audio → format/sample-rate suitable for `ndsp`.
- Target profiles: `o3ds` (aggressive), `n3ds` (default), each with texture size caps, max visible dinos, draw distance.
- Emits a budget report: estimated RAM per area; fails loudly if over budget unless `--force`.
- Add-ons for the 3DS, as on PC: the Modder's Edition as an overlay, then the add-ons, into a second pack
  (the app asks which pack at boot; each pack keeps its own save):
  ```
  cargo run --release -p c2-cook -- --game ../source/c2-original --overlay "PATH/Carnivores 2" \
      --mod ADDON --mod ADDON... --target o3ds --out modded.c2pk
  ```
- `c2-cook --check PACK.c2pk` loads a pack the way the 3DS does and plays a short hunt per animal on the PC.

### `c2-parity`
Keeps the rewrite honest.
- **Format parity**: a small C/C++ shim built from the reference source dumps parsed structures to JSON; Rust parsers must produce identical JSON for the same input.
- **Logic parity** (later): replay recorded input sequences in both, compare key state (positions, AI state, scores) at checkpoints within tolerance.
- Runs locally only (needs reference source + game data); CI uses synthetic fixtures.

## 5. Mod manifest schema (`mod.toml`)

```toml
[mod]
id = "example-raptors"
name = "Example Raptor Pack"
version = "1.0"
authors = ["Original Author"]
source_url = "https://example.com/mod-page"

[files]
# optional: explicit file classification; auto-detected if omitted
adds = ["HUNTDAT/DINO/NEWRAPTOR.CAR"]
replaces = ["HUNTDAT/MENU/MENUM.TGA"]

[res]
# _RES.TXT entries this mod adds or modifies, by entry ID (the entry's name, lower case)
adds_dinos = ["newraptor"]
modifies_dinos = []
adds_weapons = []
modifies_weapons = []

[deps]
requires = []
conflicts = []

[engine]
# features the original mod needed an exe patch for; reimplemented in c2-core
features = []
```

## 6. Recipe schema (`recipes/*.toml`)

A recipe describes a modpack **without containing any mod content**.

```toml
[recipe]
id = "ultimate-c2"
name = "Ultimate Carnivores 2"
version = "0.1"
base = "c2-vanilla"            # expected base game, verified by hashes

[[mods]]
id = "example-raptors"
credit = "Original Author"
url = "https://example.com/mod-page"
# sha256 of every file we rely on; user's copy must match
files = { "HUNTDAT/DINO/NEWRAPTOR.CAR" = "sha256:..." }

[[mods]]
id = "example-textures"
credit = "Other Author"
url = "https://example.com/textures"
files = { "HUNTDAT/MENU/MENUM.TGA" = "sha256:..." }

[load_order]
order = ["example-textures", "example-raptors"]

[[resolve]]
# explicit conflict resolutions
path = "HUNTDAT/MENU/MENUM.TGA"
winner = "example-textures"

[[patches]]
# our own small data patches (e.g. rebalance after merge), stored as text diffs
target = "_RES.TXT"
patch = "patches/ultimate-c2/res-balance.patch"
```

Workflow:
1. User downloads the listed mods into `source/mods/` (or any folder).
2. `c2-pc recipe verify recipes/ultimate-c2.toml --base <game> --mods <dir>` → reports missing/mismatched files with the URL to get each.
3. `c2-pc recipe build …` / `c2-pc play <game> --recipe … --mods <dir>` → merged pack (PC) or `c2-cook` → cooked pack (3DS).

Optional per mod: `folder = "..."` (folder name hint). `[[resolve]]` takes `path` (a file) or `entry = "characters:T-Rex"` (a `_RES.TXT` entry).

## 8. Conventions

- Rust stable for everything in `pc-ver/`; `3ds-ver/` is nightly, pinned in its own `rust-toolchain.toml`.
- `thiserror` for library errors, `anyhow` only in binaries.
- `tracing` for logs.
- No `unwrap()`/`expect()` on data from files. Ever.
- Small, reviewable commits; one milestone sub-task per commit where practical.
- Ask before: adding heavy dependencies, changing the crate layout, or deviating from original gameplay behavior.
- When unsure what the original does, read `source/c2-source/` and cite file/function in a code comment.
